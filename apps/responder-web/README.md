# MediPass Public Responder Web

React + TypeScript + Vite website opened when a responder scans a MediPass emergency QR code. No account, no install, no sign-in.

Owner: Team Member 2 (see `docs/team-handoffs/`).

## What it does

- Route `/passes/:token` calls `GET /api/v1/public/passes/{token}` on the Spring Boot API and renders a mobile-first, high-contrast emergency summary.
- `200` → renders only the categories the backend actually returned (allergies, medications, conditions, emergency contact, demographics).
- `404` → generic "link not recognized" screen. `410` → "expired" or "no longer available" screen, based on the backend's `PUBLIC_PASS_EXPIRED` / `PUBLIC_PASS_REVOKED` error code.
- Network failure → retryable connection-error screen.
- The route path (`/passes/:token`) intentionally matches the `publicUrl` the backend generates in `apps/api/.../pass/EmergencyPassService.java` (`PUBLIC_RESPONDER_WEB_BASE_URL/passes/{token}`) — keep both in sync if that ever changes.

## Security notes

- Unauthenticated by design: no `Authorization` header, no cookies (`credentials: 'omit'`), no Supabase client anywhere in this app.
- The scanned token is only ever used as a URL path segment. It is never written to `localStorage`/`sessionStorage` and never logged to the console or an analytics call.
- Unshared categories are simply absent from the API response; this app never infers, caches, or backfills a category the backend didn't send.

## Setup

```bash
cd apps/responder-web
npm install
cp .env.example .env        # VITE_API_BASE_URL, defaults to http://localhost:8080
npm run dev                 # http://localhost:5173
```

Requires the Spring Boot API (`apps/api`) running locally and its `CORS_ALLOWED_ORIGINS` to include `http://localhost:5173` (it does by default — see `apps/api/src/main/resources/application.yml`).

To try it end-to-end: create a pass from the Expo app (or `POST /api/v1/passes` directly), then open the `publicUrl` it returns, e.g. `http://localhost:5173/passes/<token>`.

## Testing

`src/api/publicPassClient.test.ts` covers the HTTP contract (200/404/410 expired/410 revoked/network error/unexpected status), including that no `Authorization` header or credentials are ever sent. `src/pages/EmergencySummaryPage.test.tsx` covers the rendered screen per state, that unshared categories never render, and that the token is never written to `localStorage`/`sessionStorage`.

Manual checklist before opening a PR (automate what you can, but at minimum eyeball these):

- [ ] Narrow mobile viewport (~360–400px wide) — no horizontal scrolling, tap targets ≥44px.
- [ ] Tested in at least two browsers (e.g. Chrome + Safari, or Chrome + Firefox).
- [ ] A QR code generated by the Expo app, scanned with a normal phone camera, opens this site directly (see `apps/mobile` README, section "Cross-device demo").
- [ ] Active, revoked, expired, invalid-token, and restricted-category passes all render correctly.
